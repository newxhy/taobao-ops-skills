# sycm-ops-daily-report 使用手册

> 一句话：**你只需要说"给某某店做个运营日报"，剩下从登录到出报告全自动。**
> 数据全部从生意参谋后台实抓，一个数字都不编。
>
> ⚠️ **它是「店铺维度」的报告** —— 分析单位是**店铺整体 / 渠道 / 推广计划**；
> **单品只出排行榜（Top10 + 一句话结构判断），不做单品纵深诊断**。
> 想看某个品"为什么不行"（渠道×词级拆解、搜索 vs 推荐结构、废词该不该删），
> 那是另一个技能 `taobao-item-channel-diagnosis` 的活。**分工是不让日报变成跑不完的怪物。**
>
> **v1.1 新增 4 个纵深维度**：逐日趋势与拐点 · 区域与时段 · 活动淡旺季节奏 · 下阶段预判。
> **v1.2 再补 3 块**：**新品与 UV 价值** · **服务健康四块** · **异常告警（三级分级）**。
> （日报从 9 段 → 12 段 → **15 段**；并修正了「7 天 vs 30 天」这个常见口径陷阱。）

技能位置：`<用户目录>\.workbuddy\skills\sycm-ops-daily-report\`

---

## 一、它能做什么（四个场景）

| 场景 | 你可以怎么说 | 它给你什么 |
|---|---|---|
| **单店日报** | "给 XX 店做个运营日报，对比前一周" | 9 段式 HTML 报告：昨日 KPI + 上周对比 + 近 7 天流量 + 人群画像 + 商品 Top10 + 推广 + 变化归因 + 风险预警 |
| **历史趋势 / 拐点** | "拉一下 XX 店最近 8 周的转化率和退款率" | N 个自然周的指标序列，自动指出"哪一周开始变了" |
| **换人 / 换策略复盘** | "看看 XX 店 7 月换运营之后有没有变好" | 换挡前后的四阶段对比 + 三线同周转向判定 + 一句话策略方向 |
| **异常归因** | "这周 XX 店怎么掉了" | 降幅结构拆解（是流量少了还是转化弱了）+ 归因判断 + 建议动作 |
| **趋势 / 节奏定位**（v1.1） | "这周比上周好了还是差了" / "现在处在什么节奏" / "下周会怎样" | 逐日曲线 + 拐点 + 周环比；活动淡旺季判定；下阶段方向与区间（不给点估计） |
| **区域 / 时段诊断**（v1.1） | "哪些省在漏水" / "什么时段该加价" | 省份明细表 + 四条地域判据（漏水 / 高潜 / 高成本 / 样本不足）+ 时段分布 |
| **新品与 UV 价值**（v1.2） | "有哪些新品" / "平台愿不愿意给我推" | 新品概览（含同行同层平均）+ 每品 **UV 价值**（支付金额 ÷ 访客数）+ **平台推荐意愿判读**（加量 / 维持 / 撤量） |
| **服务健康**（v1.2） | "客服响应怎么这么慢" / "钱都退在哪了" | 四块结论：真实体验分 · 核心监控 · 售后服务（**退款原因三分法**）· 物流洞察 |
| **历史活动对比**（v1.2） | "这次活动比上次好不好" | 选同类基准（同类 → 上一个同类 → 去年同期 → 上月日常）+ **比 UV 价值、不比累计总量** + 写明用了哪个基准 |
| **异常告警**（v1.2） | "有什么不对劲的地方" | 🔴高危 / 🟡中危 / ⚪观察 **三级列表**，每条带基准、量级与当日动作 |
| **单品排行**（只到排行榜） | "哪些品在卖" / "头部品是不是掉了" | Top10 金额 + 环比 + 退款 + **一句话结构判断**（集中度 / 谁跌出榜 / 有无黑马）。**不展开单品诊断** |
| ~~单品纵深诊断~~ | "这个品为什么不出单" | ❌ **不在本技能范围** → 用 `taobao-item-channel-diagnosis`（单品级渠道×词双轴诊断） |

## 二、前置条件（三条硬要求）

| # | 条件 | 说明 |
|---|---|---|
| 1 | **Chrome 已登录生意参谋**，且当前是目标店 | 一个账号可管多店，开工前先确认店铺对不对 |
| 2 | **bsk daemon 处于常驻状态** | 我会用后台任务拉起；没常驻就会报 `session not registered` |
| 3 | **电脑开着、Chrome 不关** | 它是在你真实浏览器里操作，做不到关机跑 |

> 不支持无头模式 / 服务器部署 / 7×24 无人值守。这是"复用真实登录态"的代价，也是它绕开风控的原因。

## 三、怎么用

直接用自然语言说就行，不用记命令。推荐句式：

- `给 XX 旗舰店做个运营日报，对比前一周`
- `我这家店这周怎么样，跟上周比比`
- `拉一下 XX 店最近 10 周的 GMV、转化率、净支付率`
- `看看 XX 店 7 月换运营之后的策略变化，用一句话总结方向`

可以附加的要求：

| 你想控制的 | 怎么说 |
|---|---|
| 换店铺 | 直接写店铺名（先在 Chrome 里切到这个店） |
| 换周期 | "对比前一周" / "对比去年同期" / "看最近 30 天" |
| 指定指标 | "重点看转化率和退款" / "只关心推广 ROI" |
| 指定周数 | "拉最近 8 周" / "从 6 月底开始" |
| 汇总力度 | "给我一句话结论" / "要详细的归因" |

## 四、输出在哪、长什么样

**落盘位置**：`<工作区>\运营日报\<店铺名>_运营日报_YYYYMMDD.html`
趋势类报告：`<店铺名>_运营策略演变对比_YYYYMMDD.html`
**原始抓取数据**：同工作区 `sycm_*.txt`（保留下来供复查，报告里每个数字都能指回去）

**日报的 15 个板块**（v1.0 的 9 段 → v1.1 的 12 段 → **v1.2 的 15 段**；★ 为新增段）：

0. 抬头（生成时间 / 类目 / 店铺层级排名 / 体验分）+ 口径说明
1. **一句话结论**（先给最反直觉的那条；**命中「高危」告警时它排第一**）
2. 昨日核心指标（6 格 KPI，含环比前一日）
3. 上周 vs 上一周期（含环比 + 自洽反算 + 月度进度）
4. ★ **逐日趋势与拐点** —— 近 14/30 天逐日曲线 + 周环比 + 哪一天开始转向
5. 近 7 天流量指标
6. 人群画像（性别 / 年龄 / 城市 Top10）
7. ★ **区域与时段** —— 省份明细 + 四条地域判据 + 时段分布（附口径天花板）
8. 商品 Top10（**排行榜 + 一句话结构判断，不做纵深**）
9. ★ **新品与 UV 价值**（v1.2）—— 新品概览（对同行同层）+ 每品 UV 价值 + 平台推荐意愿判读
10. 推广表现（分场景花费 / ROI / 广告成交占 GMV 比）
11. ★ **活动节奏定位 & 历史活动对比** —— 处在蓄水/爆发/回落哪一段 + **活动期必做跨活动对比**
12. ★ **服务健康**（v1.2）—— 真实体验分 / 核心监控 / 售后服务 / 物流洞察，四块各给结论
13. ★ **异常告警**（v1.2）—— 🔴高危 / 🟡中危 / ⚪观察 三级，逐条特别说明
14. **变化点 & 可能原因**
15. **风险预警 & 建议动作 + 下阶段预判**

> ★ 段落若本期确实取不到数据，会写「未取到」并保留小节标题 —— 让你知道这里本该有什么。

## 五、看报告前先懂这些口径

| 术语 | 含义 | 为什么重要 |
|---|---|---|
| **昨日** | 抓取日 −1 的**全天**（不是"实时"） | 首页默认落在"实时"，要主动切"日" |
| **周对比** | 上一个完整自然周（周一~周日）vs 上一周期 | 看大盘涨跌 |
| **近 7 天（滚动）** | 最近 7 个完整日 vs 前 7 日 | 比自然周灵敏，**判断趋势是否已转向靠它** |
| **月度进度** | 本月起算至今累计 ÷ 目标 | 冲刺判断 |
| **环比 vs 同比** | 环比＝较上一周期；同比＝较去年同期 | 同一张卡片上两个百分比，**报告只用环比** |
| **净支付率** | 净支付金额 ÷ 支付金额 | 每卖 100 块实际到手多少。判定"变好"最实在的指标 |
| **UV 价值**（v1.2） | 支付金额 ÷ 访客数 | **平台推荐意愿的代理指标**：高＝平台愿意继续给量（加量）；低＝平台会撤量（先改承接，别盲目加价买量） |
| **成功退款率 · 退款原因（v1.2）** | 售后服务页按原因拆分的金额占比 | 用「**主观冲动 / 规格信息 / 品质物流**」三分法看结构，避免把"该降冲动"的问题错判成"该改品质" |

**口径对照表（v1.1 新增一行）**：

| 术语 | 含义 | 用途 |
|---|---|---|
| **周环比 w/w** | 近 7 天 vs **前 7 天** | 短期动量，日报主力 |
| **月环比 m/m** | 近 30 天 vs **前 30 天** | 中期趋势，去噪 |
| **偏离基线** | 近 7 天日均 vs **前 23 天日均** | 剔除重叠后"这周偏离了多少" |

**三条口径铁律**（专门为防误判设的）：

1. **滚动 7 天与自然周必须同时给**。周口径跌、滚动 7 天涨＝下滑集中在上周前段、近期已回升。只给一个口径必然误判。
2. **不拿单日样本下结论**，比值必须能用两个绝对值反算自洽。
3. **⛔ "7 天 vs 30 天"不是趋势对比。** 30 天窗口**包含**这 7 天，两者共享约 23% 的数据，
   差异被稀释，**方向可能完全是假的**。要跨窗口比：总量指标**必须先日均化**，
   或者干脆用上表的 w/w、m/m、偏离基线三种正确做法。
   （生意参谋官方也标注过：7 天/30 天部分指标是**日均值**。）

**颜色**：沿用后台惯例 **红＝升、绿＝降**。
但退款率 / 跳失率 / 退款金额这类，**升高是变差**，报告里会额外加文字标注，避免看反。

**综合质量指标**：报告会给出每个金额的口径区间（全店/单品、是否日均），因为生意参谋各模块口径常不一致。

## 六、它的纪律（也是给你的一份承诺）

- 所有数字**实抓**，抓不到就写"未取到"，**不用估算值填空**。
- **不引用"AI 问数"**——那返回的是演示假数据（12345/23456 这种递增整数）。数字过于整齐会自动警觉。
- 百分比的正负号从页面 CSS 类名读取，**不靠文本猜**（文本里只有 `5.53%`，实际是 `−5.53%`）。
- **只读**：不点导出 / 下载 / 提交 / 改价 / 改预算。要动写操作会先问你。
- 不读 cookie / token / 密码。
- 每条结论都能指回某个具体数字。

## 七、已知限制（提前知道，少踩坑）

| 限制 | 影响 | 应对 |
|---|---|---|
| 依赖本机开机 + Chrome 登录态 | 关机 / 登录过期就抓不到 | 登录过期时在 Chrome 重新登一次 |
| 单个账号可管多店 | 可能抓到不是你想看的店 | 开工前确认"<店铺名> 主店" |
| 商品排行只覆盖**访客 Top500** | 不是全店商品 | 报告里会标注覆盖范围 |
| 交易→销售分析页会卡加载 | 拿不到该页数据 | 绕开，改用首页切"周"拿周级 GMV |
| 翻页历史有上限 | 太早的周翻不到 | 取决于店铺数据留存，左箭头变灰即到边界 |
| 访客分析时段分布不按星期拆 | 且解读文案是静态的 | 以图为准，不看文案 |
| 件数类指标可能暴跌 70%+ | 容易误读成需求崩塌 | 多半是上一周期有批量大单，报告会单独说明 |
| **地域数据不含「货品全站推广」**（v1.1） | 只能代表关键词等场景 | 报告里会写明这条天花板，不当全店地域分布用 |
| **时段数据只有店铺级、且不按星期拆**（v1.1） | 分不出"周末 vs 工作日" | 以图为准，别做周内对比结论 |
| **单品级的分时 / 地域拿不到**（v1.1） | 生意参谋侧无此维度 | 单品的区域/时段只能看推广报表（付费侧） |
| **平台大促日历只给近 1~2 个月**（v1.1） | 远期大促（如双11）还没放招商 | 技能内置大促日历表补齐远期；有新活动也会读万相台首页播报 |
| 逐日数据来自万相台（付费侧） | 反映的是**推广投放**的逐日，不是全店自然流量 | 与生意参谋的店铺级口径分开看，报告里会标注 |
| **活动效果数据有 ≥2 天同步延迟**（v1.2） | 活动刚结束当天抓，该活动的累计金额/访客可能为空或 0 | 平台明文规定；报告会标注「数据同步中」，**不会判"活动零效果"** |
| **真实体验分 / 物流洞察不是独立 URL**（v1.2） | 它们是侧栏折叠菜单的 JS 路由，单抓外层 URL 返回空 | 优先先展开父级菜单再点；仍拿不到就用替代指标并**明写「未取到」** |
| **客服单点依赖会被点名**（v1.2） | 若咨询几乎集中在 1 个客服账号，响应时长会剧烈波动 | 报告会在服务健康段指出该结构风险（属店铺维度观察，不做人事归因） |
| **不做单品纵深诊断**（设计如此，不是缺陷） | 报告里只有单品排行榜，没有该品的渠道×词级拆解 | **这是有意划的边界**：日报天天要出，越界做单品会让它跑不完；单品问题请单独跑 `taobao-item-channel-diagnosis` |

## 八、出问题怎么办

多数故障我自己会修，你只需要知道怎么描述现象：

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| 命令没反应 / 静默失败 | WorkBuddy 沙箱 PATH 损坏 | 我重置 PATH，自动重试 |
| `session not registered` | daemon 被沙箱回收 | 我重新拉起常驻 daemon |
| 数据全是"正在努力加载" | 页面异步还没拉完 | 加长等待后重抓 |
| 抓到的是别的店 | 登录态在别的店铺 | 你在 Chrome 里切换店铺后告诉我 |
| 页面要求登录 | 登录态过期 | 你在 Chrome 里重新登录 |

## 九、技能由哪三层组成

| 文件 | 层级 | 作用 |
|---|---|---|
| `SKILL.md` | 编排层 | 口径规范、抓取清单、执行流程、日报结构、坑清单、红线 |
| `scripts/bsk_grab.sh` | 取数层 | 单页抓取器：一条命令内跑完 session 建立→导航→切口径→等待→取值→收尾 |
| `templates/report_template.html` | 呈现层 | 日报骨架（**15 段**），纯占位符（**不含任何真实店铺数据**） |
| `USAGE.md` | 说明层 | 本文件 |

**分工说明**：取数路由细节复用 `sycm-backend-data-mining`；bsk 本身跑不通时先走 `bsk-browser-sandbox-setup`。本技能只管"日报怎么编排"。

**抓取器接口**（供调试参考）：

```
bsk_grab.sh <URL> <输出文件> [点击文本] [等待毫秒] [导航超时毫秒] [自定义JS]
例：bsk_grab.sh "https://sycm.taobao.com/portal/home.htm" out.txt "周" 14000 12000 "$JS"
```

## 十、进阶一：挂成定时任务

可以让它**每周一早上自动出上周复盘**（或每天早上自动出前一天日报）。

两种做法：

| 方式 | 说法 | 适合 |
|---|---|---|
| **定时任务** | "挂成每周一 9 点自动出 XX 店的周报" | 固定节奏、不用你开口 |
| **临时触发** | 每次直接说"给 XX 店出日报" | 按需、灵活 |

> 提醒：定时任务同样依赖**本机开机 + Chrome 已登录**，做不到关机也能跑。

## 十一、v1.1 新增能力怎么用

### 1）趋势 / 节奏：直接问"这周比上周好了还是差了"

报告会给**逐日曲线**（近 14 或 30 天）+ **周环比** + **拐点**（哪一天开始转向），
而不是只丢给你两个快照。判读时会**把规模（访客/展现）和效率（转化/点击率/CPC）分开看** ——
因为「访客涨但转化跌」和「访客跌但转化涨」是完全相反的两件事。

### 2）区域 / 时段：直接问"哪些省在漏水"

报告会给省份明细表，并套用四条判据自动标出：

| 判据 | 阈值 | 看到它该做什么 |
|---|---|---|
| **漏水区** | 点击 ≥ 20 且成交 = 0 | 压价或屏蔽（**不是**加价） |
| **高潜区** | 转化率 ≥ 均值 × 1.5 且 CPC ≤ 均值 | 加价抢量 |
| **高成本区** | CPC ≥ 均值 × 1.5 | 压价 |
| **样本不足** | 点击 < 20 | 不下结论 |

> 特别提醒一条容易做反的：某省**有点击、点击率也不低、但 0 成交** ——
> 这不是"位置不好"，是"**人不配**"（该地人群跟你的品不匹配），
> 动作是**屏蔽 / 压价，绝不是加价换位置**。

### 3）活动淡旺季节奏：报告会先告诉你"现在处在哪一段"

同一个数字，在**蓄水期**和**回落期**含义完全相反。所以报告会先定位节奏再归因：

| 阶段 | 特征 | 怎么看 |
|---|---|---|
| **蓄水期**（大促前 2~4 周） | 加购↑、成交平、**ROI 掉** | 只看加购，**绝不看 ROI**（ROI 掉了不是坏事） |
| **爆发期** | 成交暴涨、ROI 虚高 | 自然成交会被算进付费功劳，别当效率真提升 |
| **回落期** | 成交跌破日常 | **不能判"衰退"**，要跟去年同期或上一个非大促月比 |

另外会自动区分**波动品类型**，避免用错基准把好品判死：
**季节品（服装）用同比、事件品（出行场景品）绑外部日历、稳定品才用环比**。

### 4）下阶段预判：只给方向，不给算命

报告会给：**区间外推**（方向 + 幅度区间）+ **拐点预警**（蓄水/衰竭/透支信号）+ 
**未来 30 天该盯的 3 个指标（含触发阈值与动作）**。

> **界限说明**：不会给"下 7 天卖 123 单"这种点估计 —— 小店铺日数据量撑不住精确预测。
> 有活动/节日时误差会显著放大，报告里会标注"是否含活动修正"。
> **AI 的预测是参考，不是依据。**

## 十一·补、v1.2 新增三块怎么用

### 1）新品与 UV 价值：直接问"平台愿不愿意给我推"

商品排行**只覆盖访客数 Top500** —— **新品量还没起来就排不进榜**，新品多的店会整批漏掉。
所以 v1.2 会单独看「**商品 → 新品追踪**」页，给每个新品一个 **UV 价值 = 支付金额 ÷ 访客数**：

| UV 价值 | 平台会怎么做 | 你该做什么 |
|---|---|---|
| **高于同行同层平均** | 继续给量 / **加量** | 加预算、加库存、**别乱动价格** |
| **≈ 同行平均** | 维持分发 | 优化主图 / 详情页 |
| **明显低于同行** | **撤量**（流量给更高效的品） | **先改承接**，别盲目加价买量 |

> **两种病，两种药（最容易搞反）**：
> **UV 价值高但访客极少** = 平台还没发现你 → 动作是"**让它被看见**"；
> **UV 价值低但访客很多** = 平台给了量你没接住 → 动作是"**改承接**"。
>
> 另外：**新品不要跟老品比 UV 价值**（老品有积累，天然更高），要**同批新品横向比**。

### 2）服务健康：直接问"钱都退在哪了 / 客服怎么了"

报告会给四块结论，并**用平台自己标的「同行同层优秀」当合格线**（不用我拍阈值）：

| 块 | 关键项 | 有什么用 |
|---|---|---|
| 真实体验分 | 分数 + 是否「规则不达标」 | 店铺权重健康度 |
| 核心监控 | **平均响应时长**、3 分钟人工响应率、满意率、客服排名 | 响应时长是**最灵敏的恶化先行指标** |
| 售后服务 | **成功退款率** + 退款原因结构 | 看钱到底为什么退 |
| 物流洞察 | 揽收 / 运输 / 派送时效 | 退款诱因的上游 |

**退款原因会用「三分法」归类**，这决定了动作方向：

| 类别 | 典型原因 | 动作方向 |
|---|---|---|
| **主观冲动** | 不想要了 / 拍错多拍 / 买贵了 | **降冲动**（预期管理 / 发货速度 / 催付话术） |
| **规格信息** | 规格尺码颜色拍错 | **改 SKU 说明 / 加尺码引导** |
| **品质与物流** | 质量问题 / 破损 / 快递未送到 | **改品控 / 换物流** |

> **最容易搞反的一条**：如果主观冲动类占了退款的**大头**，
> 那"去改品质"就是**打错靶子** —— 正确方向是"**降冲动**"。
>
> 另外，「质量问题」的 `完结退款率` 若显示 >100%，那是**以前申请、本期才完结**（滞后兑现），
> **不代表本期质量突然变差**。

### 3）异常告警：报告开头会有一张"报警表"

不用你自己在数字里找问题 —— 命中阈值的会**单独成段、分三级列出**：

| 级别 | 什么时候给 | 报告里怎么写 |
|---|---|---|
| 🔴 **高危** | 环比恶化 ≥50% ／ 突破「同行同层优秀」1.5 倍 ／ 平台标了「请关注」/「规则不达标」／ 有明确资金或流量损失 | **进一句话结论第一条** + 独立条目 + **给当日动作** |
| 🟡 **中危** | 环比恶化 20%~50% ／ 结构性转差 | 独立条目 + **观察窗口**（下次什么时候再看） |
| ⚪ **观察** | 环比恶化 <20% ／ **样本不足**（点击<20 / 访客<50 / 展现<200） | 一句话 + 标明样本量，**不下结论** |

**每条告警都会写清三件事**：**现象**（哪个指标、多少）→ **量级**（对谁比、几倍）→ **动作**（今天做什么）。

> **另外它会主动替你做"反向校验"**：有些看起来的"恶化"其实**是健康的**，报告会点明，避免误杀 ——
> ① **灌量退潮**（访客大跌但转化大涨 = 回到真实基本盘，不是衰退）；
> ② **蓄水期 ROI 掉**（大促前正常，该看加购）；
> ③ **退款率升伴随客单价升**（高单价品退款率天然更高）；
> ④ **金额退款率升但笔数退款率降**（是单笔金额结构变了，不是退款变多）。

### 4）历史活动对比：活动期不会再拿"日常"当尺子

如果出报告的时点**落在活动进行中、或活动刚结束 7 天内**，报告会额外做一步：
**用同类活动当基准**（同类活动 → 上一个同类 → 去年同期 → 上月日常），而不是拿日常环比。

> **关键铁律**：活动时长不同（3 天 vs 20 天），**累计金额直接比是错的**。
> 正确做法是算 **UV 价值 = 累计支付金额 ÷ 累计引流访客数**，**比值才可比**。
>
> 报告会**写明用了哪个基准、为什么用它** —— **基准选错 = 系统性误杀**（把旺季品当衰退品砍掉）。
