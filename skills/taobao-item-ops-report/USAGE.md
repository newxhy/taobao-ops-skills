# 单品运营报表 · 使用说明

## 30 秒上手

```bash
# 1) 渲染（示例数据随包附带，可直接跑通）
python scripts/gen_report.py assets/example_data.json 输出.html

# 2) 校验（标签配平 / 占位符 / 段落数 / 推广三行自洽）
python scripts/verify_report.py 输出.html
```

- **零依赖**：只用 Python 标准库（`io` / `json` / `re` / `sys` / `os`），无需 pip 安装任何东西
- **示例产出**：`assets/example_report.html` —— 用示例数据生成，**可直接打开看效果**
- **数据格式**：一个 UTF-8 的 JSON，键名 = 模板里的占位符名（见 `assets/item_report_template.html` 顶部注释的全量索引）
- **缺失即「未取到」**：值写 `null` / `""` / 干脆不写，都会渲染成「未取到」。**禁止估算**

## 二、什么时候**不用**它

- **想看整个店**（渠道构成、推广计划健康、多品对比）→ 用店铺维度的日报技能，本技能是**单品**口径
- **想做纵深诊断**（渠道 × 词双轴、找位、该投该否词表、多品优先级排序）→ 用单品纵深诊断技能
- **想让我直接改价 / 改券 / 调预算** → ⛔ 本技能**只读**。所有写操作由人执行

### 三条填写纪律

1. **方向类键**（`…方向` / `…色`）= CSS 类名，**只能填** `up` / `down` / `flat`（`…色` 填 `lvl0`~`lvl3`）
   —— 填错会渲染成无色，但不会报错，**所以要自己核对**
2. **数值列**照抄页面显示（含千分位没问题），校验器会自行去格式化后相加
3. **HTML 片段**（如 `券时间线`、`渠道N标签`）可以内嵌 HTML —— 它们是原样插入的

## 五、渲染与校验会告诉你什么

`gen_report.py` 输出：

```
写出: 输出.html
字节: 34810
裁剪空行: 45 行          ← 只给了 14 天逐日，后 7 行自动裁掉
残留占位符: 0  ✓
未提供 N 个键（已写「未取到」）: …
```

`verify_report.py` 输出：

```
  ✓ 标签配平        全部配平
  ✓ 残留占位符      0
  ✓ 段落完整性      h2 = 15（期望 15）
  ✓ 垃圾值         无
  ✓ 表格结构        列数一致
  ✓ 推广三行自洽     花费 2240.6+823.4+16.4=3080.4 vs 合计 3080.4 ✓
```

**推广三行自洽**是本技能内置的硬校验：
**全站推广 + 关键词推广 + 店铺直达 = 合计**（花费与点击各验一次）。
只列前两行一定对不上合计 —— 差额就是「店铺直达」。

## 六、常见问题

**Q：跑出来很多「未取到」怎么办？**
A：那是**正确行为** —— 报表宁可留白也不许估算。把对应事项写进「待确认清单」。

**Q：行数不够 / 太多？**
A：模板按固定行数预留（逐日 21 行、渠道 10 行、告警 12 行…），
**给几条渲染几条**，空的整行自动裁掉。

**Q：能改成我自己的视觉风格吗？**
A：可以。模板是单个 HTML 文件，CSS 集中在顶部 `<style>`。
改模板**不会**影响脚本逻辑。

**Q：为什么强调「不给原因只给引导」？**
A：因为转化类异常可由几十种原因造成，**其中很多原因的数据形状完全相同**
（例：跳失率↑+人均浏览↓ 既可能是比价失败、也可能是承接变差，**药方相反**）。
只凭数据形状下结论，有接近一半概率**把药方开反**。
所以本技能的产出是「**发现变化 + 列出候选因素 + 指向确认人**」，
由**人**完成最后一步确认。详见 `references/attribution-gates.md`。

## 七、输出与分享

生成的 HTML 是**自包含**单文件（无外链资源），可直接：
- 用浏览器打开 / 发给运营 / 存为归档
- 需要 PDF 时用浏览器「打印 → 另存为 PDF」

> 本技能**只读**：不执行任何改价、改券、调预算、暂停计划的操作。
