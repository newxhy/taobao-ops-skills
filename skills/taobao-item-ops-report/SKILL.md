# 淘宝单品运营报表

为一个**商品**生成周期性的运营报表：多周期指标 + 渠道结构 + 转化漏斗 + 推广效率 +
归因闸 + 需人工确认清单 + 异常分级，输出一份可直接交付运营的 HTML 长报告。

---

## 0. 总纲：本技能的第一性原理（先读，再往下）

这七条决定了报表**该写什么、不该写什么**。违反其中任何一条，报表的价值归零甚至为负。

### ⓪ 报表的唯一目标：发现变化 → **引导找到原因**（最重要的一条）

> **单纯的报表意义不大。** 一份好报表不是"数据陈列"，而是**一条闭环**：

```
发现数据变化 →  描述变化的数据形状  →  引导运营去查对应方向  →  运营确认事实  →  动作
      ↑                                                                          │
      └───────────────────────  下期验证是否闭合  ←─────────────────────────────┘
```

**唯一自检标准**：运营拿到报表后，**知道下一步该去问谁、查什么**吗？
如果运营看完只能说"哦，知道了" —— **这份报表就是失败的**，不管它的图表做得多漂亮。

**三条硬规定**：

1. **每一条变化，都必须配一条引导。** 不许只列数字不给方向。
2. **引导必须具体可执行。**
   「去券后台查该品券的生效区间有没有断裂」✅ ／ 「关注转化情况」❌
3. **引导的形态是"问题"，不是"断言"。**
   「上周是否调整过价格 / 优惠券？」✅ ／ 「券缩水导致转化下降」❌（后者是未经验证的结论）

> **分工**：**AI 做前半段（发现变化 + 生成引导），人做后半段（确认事实 + 执行动作）。**

这条是 §0 其余六条的目的；那六条是实现它的纪律。

### ① 突变必有因 —— 数据不会自己变坏

看到突变（转化掉、流量涨、ROI 崩），**第一动作是找"谁动过什么"**，
而不是**给现象起名字**。可能动过的主体：

```
自己（价格 / 券 / SKU / 主图 / 详情 / 包邮门槛 / 库存）
平台（规则 / 流量分配 / 活动排期 / 工具下线）
竞店（券后价 / 赠品 / 运费 / 主图 / 报名活动）
环境（节令 / 假期 / 物流停运 / 行业大盘）
```

### ② ⛔ 给现象命名 ≠ 找到原因

「流量质量下降」「承接能力不足」「跳失率变差」「人群不精准」——
这些是**现象的描述**，**不是归因**。

> **把它们当原因写进报表，是本技能最大的失败模式。**
> 它们**不报错、看起来专业、还押着韵**，但药方会开反。

**实测教训（一次真实的翻车）**：某单品转化率环比 −47.80%，报表给的归因是
"承接质量恶化"（跳失率↑、人均浏览↓）→ 药方"改详情、加客服"。
**真相是优惠券力度从 9 折缩到 92 折、不再比同品牌专卖店便宜** → 买家进店比价后离开。
**跳失率↑ / 人均浏览↓ 是"比价失败"的形状，与"承接差"形状相同、药方相反。**

### ③ 能查的用数据查实，查不到的列清单 —— 绝不自己编

| 类型 | 举例 | 怎么做 |
|---|---|---|
| **数据能查** | 券力度与生效日、活动报名、SKU 上下架、价格、退款原因、推广结构 | **去后台查实**，不猜 |
| **数据查不到** | 运营自己动过什么、竞店改了什么、线下沟通、工厂供货、真实库存 | **写成「需人工确认清单」**（见 §5.13）交给运营/店主 |

**"瞎猜"的定义**：用**现象描述**冒充**归因**，且**没有验证路径**。

### ④ 转化类异常的第一问永远是："我们自己上周动过什么？"

顺序：**价格 / 优惠券 / 满减 / SKU / 主图 / 详情 / 包邮门槛 / 库存** —— 先自查，
再谈竞店，最后才谈流量与投放。**放最后，别一上来就调价。**

### ⑤ 必须把「运营人为失误」列为高优先假设

人为失误**不报错、不留痕、看起来像"自然下滑"**，所以最容易被误判成"经营问题"去优化。

**四类典型**：
- **优惠券到期忘记续期** → 出现**无券空窗**（看券的可用时间区间是否断裂）
- **活动结束后忘记重启优惠券** → 活动期配的券是独立批次，活动一停就失效
- **误改价 / 误下架 SKU / 误改主图** → 转化或点击率台阶式变化
- **改完忘记改回来** → 大促前的临时设置留在日常

### ⑥ AI 的职责边界：只列因素 + 指向确认人

**关联转化的因素太多，单靠数据无法穷举。** 所以本技能的产出**不是"给出原因"**：

| 角色 | 职责 |
|---|---|
| **AI（本技能）** | ① **发现数据变动**（AI 的地盘）② **列出候选因素清单** ③ **指向确认人与查法** |
| **运营 / 店主** | ① 确认事实（上周动过什么）② 去竞店看 ③ 执行动作 |

→ **报表里出现"承接能力不足"这类现象名称却没有验证路径 = 越界 + 瞎猜。**

## 3. ⛔ 取数铁律：禁止脆弱定位（最高优先级）

> **禁止依赖全页面文本顺序、`indexOf`、固定位置等脆弱定位方式。
> 必须先定位指标自己的结构化容器，再从该容器内部提取数值、趋势、排行、单位和时间范围。**

**为什么是最高优先级**：数字为真、但**语义归属错了** —— 它**不报错、不崩、看起来正常**，
却会把"转化前 8%"读成"前 53%"，据此下一个完全相反的结论。
**错误数据比没有数据危害大十倍。**

### 四步强制流程

1. **先 dump 原始 token 序列**（带 index + `repr`）—— **不是先写解析逻辑**
2. **找锚点 token 反推 offset** —— 不用 `indexOf`，不用"第 N 个数字"
3. **写断言**：关系不成立时返回 `None`（**宁缺勿错**，宁可写"未取到"）
4. **数学恒等式交叉校验**（容差 ±3%）

### 实战教训

**「数据在、解析不出」的第一动作永远是 dump token 序列，不是改解析逻辑。**

> 实测：某后台页面的数据已抓到，但解析全 `None`。连续两轮改解析逻辑无效；
> **dump 一眼就看出 offset 猜错了** —— 真实结构是六元组
> `标签|值|较日常|涨跌|同类商品排行|分位`，标签在「较日常」**前二位**（猜的是前一位，取到了值）。

### 必做的自洽校验（每次出数后都跑）

```
分日加总      == 页面区间合计
场景明细加总  == 场景合计
计划明细加总  == 计划合计
派生比率      == 由原始值重算（ROI = 成交÷花费、转化率 = 买家÷访客、CPC = 花费÷点击）
跨后台锚      某后台的"分花费" == 另一后台的分日加总（同区间）
```

**推荐做法**：直接用 `scripts/verify_report.py`，它把上述检查内置为可复用清单。

## 4. 执行流程（六步）

### 第 1 步 · 定目标与口径
1. 确认**目标商品**（商品 ID / 标题片段）与**店铺登录态**
2. 导航后**先断言 `location.href`**，确认落在预期页面（防止取到上一页缓存）
3. 定周期：**昨日 / 上周vs前一周 / 近7天vs前7天 / 逐日（≥14 天）**
4. **总量指标一律日均化**再比较（禁止"7 天总量 vs 30 天总量"——两窗口重叠，方向会假）

### 第 2 步 · 抓数
按 §2 清单逐页抓，**每页一 session**，落盘原始文本（`_raw.txt`）再解析。
**先 dump 再解析**（§3）。

### 第 3 步 · 自洽校验
跑 §3 的恒等式清单。**任何一条不过，先查数，不要写结论。**

### 第 4 步 · ★ 过归因闸（顺序不能跳）
完整定义见 `references/attribution-gates.md`。**顺序**：

```
闸零 · 自身变更（价格/券/SKU/主图/详情/包邮/库存）   ← 最易忘、最可控
闸一 · 竞店对标（同品牌专卖店 / 同类竞品的券后价、赠品、运费）
闸二 · 口径成熟度（归因未回补日是否混进分子分母；两窗口成熟度是否一致）
闸三 · 供给（断码 / 断色 / 断规格 / 断货）
闸四 · 日历（大促 / 节令 / 假期 / 物流停运）
闸五 · 节奏（蓄水期 / 爆发期 / 回落期，见 §6.7）
闸六 · 投放（流量 / 出价 / 创意）  ← 放最后，别一上来就调价
```

**每闸必须显式写"已查 / 未查"**，未查的进 §5.13 清单。

### 第 4.5 步 · ★★ 生成引导清单（**这一步才是报表真正的产出**）

按 §0⓪：报表的价值 = 发现变化 × **引导质量**。

1. 把本次所有异常**逐一认形**（对照 §6.11 的形状表）
2. 每条形状 → 一条**问句形态**的引导，带上"去查什么 / 去问谁"
3. 分两栏：**AI 已自查**（自己查完，不推给人）／ **待人工确认**（推给运营）
4. **顺序强制**：先把 AI 能自查的查完，再交清单 —— 否则等于把自己的活推给人

> ⛔ 少了这一步，前面的抓数、校验、渲染**全部白做**。

### 第 5 步 · 渲染
用 `assets/item_report_template.html` 作骨架，`scripts/gen_report.py` 负责
「数据 JSON → 填占位符 → 输出 HTML」。**取不到的值写「未取到」+ 保留小节标题**
（读者要知道这里本该有什么）。

### 第 6 步 · 校验与交付
1. 跑 `scripts/verify_report.py`：标签配平 / 占位符残留 / 恒等式反算
2. 交付 HTML，并附 **需人工确认清单**（§5.13）

## 5. 报表结构（15 段）

> 段落顺序即**阅读顺序**：先看现状（一~三）→ 再看结构（四~七）→ 再看外部与推广（八~十一）
> → 最后看归因与动作（十二~十五）。

| 段 | 标题 | 写什么 | 易错点 |
|---|---|---|---|
| 一 | **一句话结论** | 3~5 条：当前处境 / 最大异常 / 最该做的一件事 | 不许写现象名称当结论 |
| 二 | **核心指标卡** | 昨日 / 上周vs前一周 / 近7天vs前7天 **三周期并排** | 单周期不给结论 |
| 三 | **周期对比总览** | 多周期口径明细表 + **口径标注** | 总量须标"日均"还是"合计" |
| 四 | ★ **逐日趋势与拐点** | 分天粒度；**归因未回补日单独标注并给剔除后值** | 未剔除会造出假下降 |
| 五 | **流量结构** | 渠道构成（搜索/推荐/付费/购物车/我的淘宝/店铺…）→ **主动 vs 被动标签** | 推荐流量涨≠你的功劳（§6.6）|
| 六 | ★ **效率 × 规模二维** | 各渠道落在哪个象限 | "访客↑转化↓"≠增长（§6.1）|
| 七 | **转化漏斗与先行指标** | 访客→加购→成交；**购物车兑现率**；先行/滞后指标分离 | 用成交判养词期 = 误杀（§6.3）|
| 八 | **价格与优惠位** | 券档位结构 / 券后价 / **无券空窗检测** / 与竞品对比位 | 只看标价不看券后价 |
| 九 | **推广表现** | **三组件三行自洽**（全站 / 关键词 / 店铺直达）+ 词级漏水区 + 点击率门槛 | 合计对不上行和（§6.9）|
| 十 | **人群与词** | 人群画像 + 该投/该否词（精简版，纵深交付另一技能）| 词样本不足别下结论（§6.5）|
| 十一 | **商品自身健康** | SKU 上下架 / 断码断色 / 评价差评 / 主图详情是否改过 | 全归因到"承接"的常见源头 |
| 十二 | ★★ **归因闸结果 + 需人工确认清单**（**本报告的核心交付物**）| 七闸逐条"已查/未查/结论" → 汇总成**引导清单**（问句形态 + 指向确认人 + 说明查法）| ⛔ 不许省略；**没有引导清单的报表 = 失败的报表**（§0⓪）|
| 十三 | ★ **异常告警分级** | 🔴 高危 / 🟡 中危 / ⚪ 观察 | 倍数级恶化与破阈值**必须单独成段** |
| 十四 | **变化点 & 风险/机会/盯数** | 变化点 + 风险 + 机会 + 下阶段要盯的 3 个数 | — |
| 十五 | **诚实边界与口径说明** | 哪些数没取到、口径是什么、哪些结论有前提 | 取不到的**不许估** |

### 5.13 ★★ 需人工确认清单（**本报告的核心交付物** · 格式固化）

**这是报表价值的落点**（§0⓪）：运营拿到它，就知道**去问谁、查什么**。

- **怎么生成**：用 §6.11「数据形状 → 引导问题」对照表，挑出本次命中的行
- **形态要求**：**问句** + 指向**人** + 可执行的**查法**；**不许写成断言**
- **怎么分工**：**AI 能自查的必须先查完**（券后台、计划状态、SKU 状态、退款结构…），
  只把**查不到的**留给运营 —— 不要把能自己查的也推给人

**表格三列**，下面这些是**候选行**（按实际情况勾选 / 增补）：

| # | 待确认事项 | 现象特征 | 去问谁 |
|---|---|---|---|
| 1 | **上周是否调整过价格 / 优惠券 / 主图 / 详情 / SKU / 包邮门槛？** | 转化台阶式变化 | 运营 |
| 2 | **该品的券有没有到期没续？**（查券的可用时间区间是否断裂）| 无券空窗 | 运营 / 券后台 |
| 3 | **主推 SKU 有没有断码 / 断色 / 断规格 / 断货？** | 单品转化↓、推广花费正常 | 运营 / 库存 |
| 4 | **同品牌其他专卖店 / 同类竞品的券后价、赠品、运费变了吗？** | 进店即离（跳失↑ + 人均浏览↓）| 运营去看 |
| 5 | **主图 / 详情 / 标题上周改过吗？** | 点击率↓ 或 转化↓ | 运营 |
| 6 | **该品报没报活动？活动期的临时设置有没有改回来？** | 活动前后台阶 | 运营 |
| 7 | **评价区有没有新增差评 / 问大家出现集中疑问？** | 转化↓ 且客服咨询↑ | 运营 / 客服 |

## 6. 核心判据库（速查）

### 6.1 效率 × 规模二维
**永远二维看，不看单一维度。**
`访客 ↑ 而 转化 ↓` = **承接没跟上，不等于增长**；`访客 ↓ 而 转化 ↑` = 流量变准，未必是坏事。

### 6.2 先行指标 vs 滞后指标（关键）
- **成交是滞后指标，加购是先行指标。**
- **高客单品 / 大促蓄水期 / 养词冷启动**三个场景，**必须切到加购率 + 加购增速**；
  **用成交去判会系统性误杀。**
- **购物车兑现率 = 成交 ÷ 加购**，须做**时间序列**（涨 = 承接改善；跌 = 比价 / 凑单）。

### 6.3 「加购率高」的三种假阳性
**加购率高 ≠ 好事**：① 凑单加购 ② 比价加购 ③ 价格等待加购。
**同一条数据在不同场景结论相反**（加购 > 0：低客单 = 比价词该删；高客单/活动前/养词 = 该养）。

### 6.4 漏水区判据
**点击 ≥ 20 且成交 = 0** 的词/渠道 → 压价或屏蔽。

### 6.5 样本门槛
**点击率判读需展现 ≥ 200**；小样本下先看"**有没有量**"，再看"**效率好不好**"。
低于门槛只写"样本不足，不判读"。

### 6.6 推荐流量暴涨 ≠ 你成功了
平台 = 房东 / 广告商，流量是有限面积，分配目标是**整盘转化最大化** + **保住议价权**。
平台会**主动给效率低的品也灌量**防头部垄断 →
**推荐流量涨而转化低是常态，不是故障**。

**三个必问**：
1. 看推荐流量：这是平台在**服务我**，还是在**平衡它自己**？
2. 看付费流量：买到的是**增量**，还是从我自己**自然流量迁移**过来的？
3. 看付费 ROI：**平台口径**还是**我重算的**？

### 6.7 波动品先打「波动类型」，再选基准
| 波动类型 | 基准 | 用错基准的后果 |
|---|---|---|
| **季节品**（服装等）| **同比** | — |
| **事件 / 场景品**（如出行相关）| 绑**外部日历**（春运/暑运/黄金周）| 拿事件品淡季环比会砍掉旺季能爆的品 |
| **稳定品** | 环比 | — |
| **新品** | 不与老品同基准 | — |

**大促三段结构**：蓄水期只看**加购率 + 加购增速**、不看 ROI ／ 爆发期 ROI 虚高 ／
**回落期不能判"衰退"**（须同比）。两个反常识：
**大促前日常流量会掉**（平台把免费流量导向会场）；**大促后必然回落**（需求被提前透支）。

### 6.8 归因成熟度（会凭空造出"下降"）
万相台未回补日的**成交显示 0.00**。若把这段**算进分母、却没算进分子**：
转化率与成交被**机械性压低** → 造出一个不存在的"暴跌"。

**必须披露**："本窗口内有 N 天成交 0.00（M 点击，占 X%）"，并给出**剔除后**的值。
判定标准：
- **T-1（昨日）** 显示 0.00 → **正常**，归因未回补
- **T-2 / T-3** 仍 0.00 → **列入观察**，并标注**复核日**
- **超 15 天窗口**仍 0.00 → 才可判真零

### 6.9 推广三组件必须自洽
万相台账户合计 = **全站推广 + 关键词推广 + 店铺直达**。
⚠️ **只列前两项，合计一定对不上**（差额就是"店铺直达"）。
**每行都要有"花费 / 点击"两列**，让读者能自己加总复核。

### 6.10 口径陷阱清单
- **「7 天 vs 30 天」不是两个独立样本**（30 天包含这 7 天）→ 用**周环比**或**近 7 天 vs 前 23 天**
- 生意参谋官方声明：7 / 30 天是**日均值**
- **「进步 / 退步」是分位名次的变化，不是指标值的变化**（转化率没降也可能标"退步"）
- **「支付买家数」≠「支付件数」**（一个去重人、一个件数）→ 换算并**显式标注**
- **URL 口径参数会被页面默认值静默覆盖** → 三步强制：URL 带全参数 → 导航后点按钮 → **读数前断言**

### 6.11 ⭐ 数据形状 → 引导问题（本技能的核心工具）

把「发现的变化」翻译成「运营能执行的问题」的对照表。

**用法**：抓到数据后，先认形状，再从这张表挑出**本次命中**的行（通常 3~6 条），
直接组成 §5.13 的需人工确认清单。
**纪律**：表里的"高概率方向"是**候选**，不是结论 → 写成**问句**，不写成断言。

| 数据形状 | 高概率方向（候选，≠结论）| 引导去查 / 去问 |
|---|---|---|
| **转化台阶式下跌，流量正常** | 自身价格 / 券 / SKU / 竞品 | 问运营：「上周是否调整过价格、优惠券、SKU 或包邮门槛？」＋ 查券后台的券档位与生效区间 |
| **跳失率 ↑ 且人均浏览 ↓** | ⚠️ **形状双解**：比价失败 **或** 承接变差 | **两句都要问**：① 券后价是否已高于同品牌专卖店？② 主图/详情上周改过吗？**不可只问其中一句** |
| **点击率 ↓，展现正常** | 主图/创意变差 或 词放量到泛词 | 问：「主图/创意上周改过吗？」＋ 查词构成里有没有新进来的大词、泛词 |
| **展现 ↑、点击 ↑、转化 ↓、CPC ↓** | **买偏了** —— 量买到了、意图没买到 | 查全站推广的匹配是否放宽；让运营看推广流量的人群与词是否跑偏 |
| **加购 ↑ 但成交 ↓** | 购物车兑现率下降（比价 / 凑单 / 等降价）| 查券力度是否缩水；问竞品券后价；区分"凑单加购"与"真需求加购" |
| **访客 ↓ 但转化 ↑** | 流量变准（未必是坏事）| **先别动** —— 结合波动类型（§6.7）判断是否为节令/大促前的正常收缩 |
| **某渠道 / 某计划花费突降或归零** | 计划被暂停 / 预算耗尽 / 计划下线 | 查该计划的状态与预算（**AI 自查**）；越权动作须运营确认 |
| **成交显示 0.00（近 1~3 天）** | 归因未回补 | **不是事故** —— 见 §6.8；超 3 天仍 0 才列入观察 |
| **退款率 / 差评突增** | 品质 / 物流 / 描述不符 | 看退款原因结构（§7 第 7 条三类药方不同）；看评价区的具体内容 |
| **客单价突降** | 促销结构变了 / 低价 SKU 占比上升 | 查券档位与实际成交价带；查 SKU 销量结构 |
| **某 SKU 销量归零** | 断码 / 断色 / 断规格 / 下架 | 问运营：「该 SKU 还有货吗？是不是下架了？」 |
| **该品跌，但全店排行里其他品也跌** | **不是单品问题** | 升级为店铺/大盘问题 → 交给店铺日报技能，别在单品层面瞎修 |
| **波动与前一年同期同形** | 季节性 | 换**同比**基准（§6.7），不要用环比判衰退 |
| **现象与上次大促前后同形** | 大促蓄水/回落 | 对照大促日历；蓄水期看加购不看 ROI |

> 🔑 **这张表就是本技能的成长记录**：每次实战发现"新形状 → 新方向"的对应关系，
> **当场追加一行**。表越长，引导越准，报表越值钱。

## 7. 坑清单（实测踩到的）

1. **首页 / 概览类卡片的"总花费·总点击·总 ROI"三行，切换周期时不刷新** → 残留值，**弃用**
2. **万相台 hash 路由必须整条带 `?rptType=`**（如 `#!/report/item_promotion?rptType=item_promotion`），
   只写 `#!/report/xxx/index` 会落到错页
3. **「周」不滚动**（周五/周六读"周"仍是上周日~上周六）→ 改用滚动 7 天
4. **懒加载**：列表首次渲染常只出 8~9 行；个别品整块缺字段 → **断言返回 `None`，不许凑数**
5. **店级指标不能当单品指标**（地域报表、访客分析多为**店铺级**）→ 使用时**必须标注代理关系**
6. **地域报表不含全站推广**（页面自述）→ 若主力在全站推广，地域结论**只代表关键词场景**
7. **退款原因结构 ≠ 责任归属**：主观冲动（不想要了/拍错/协商一致）→ 降冲动；
   规格信息 → 改 SKU；品质物流 → 改品控。**三类药方完全不同**
8. **页面上的"优化建议"是广告，不是数据**（如"点击率落后同水平商家"、"一键升级智能优化"）
   → **不要引用为证据**
9. **点击率低 ≠ 该加价**：分两种 ——
   "位不值" → 调价换位；"人不配" → **否词**。**绝不能加价**

## 9. 已知边界（诚实声明）

- **淘系限定**：数据源与字段均为淘宝 / 天猫后台；拼多多 / 抖音 / 京东字段口径不同，**不可直接套用**
- **单品级地域 / 分时拿不到**：地域与时段多为**店铺级** → 只能作代理并标注
- **需要登录态**：本技能不做登录、不代持凭据；由运行环境的浏览器会话提供
- **只读**：本技能**绝不执行任何写操作**（改价、改券、调预算、暂停计划）——
  **所有动作由人执行，报表只出意见与路径指引**
- **AI 不给出未经数据验证的"原因"**：查不到的，一律进「需人工确认清单」（§5.13）
