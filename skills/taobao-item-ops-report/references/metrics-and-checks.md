## 1. 指标口径定义（出数前先对齐）

### 1.1 基础指标

| 指标 | 定义 | 易错点 |
|---|---|---|
| **访客数（UV）** | 去重的**人** | 与"浏览量（PV）"是两回事 |
| **浏览量（PV）** | 页面访问**次数** | PV ↑ 而 UV ↓ → 人均浏览 ↑ |
| **支付买家数** | 去重的**人** | ⚠️ **≠ 支付件数** |
| **支付件数** | 成交的**件**数 | 与买家数换算须**显式标注** |
| **支付子订单数** | 拆单后的子订单 | 与服务/物流指标关联 |
| **支付金额** | GMV | 区分"支付金额"与"净支付金额" |
| **客单价** | 支付金额 ÷ 支付买家数 | 用**人**不用**件** |
| **件单价** | 支付金额 ÷ 支付件数 | 与客单价**不同**，别混 |
| **支付转化率** | 支付买家数 ÷ 访客数 | 分母是 UV |
| **跳失率** | 只看 1 页就离开的比例 | **升 = 变差**（与其他指标方向相反，必须标注）|
| **人均浏览量** | PV ÷ UV | 承接质量的代理指标 |
| **加购人数** | 加入购物车的人 | **先行指标**（§SKILL 6.2）|
| **UV 价值** | 支付金额 ÷ 访客数 | 一行一品的**综合效率** |

### 1.2 派生指标（必须自己重算，不用平台给的）

| 指标 | 公式 | 用途 |
|---|---|---|
| **购物车兑现率** | 成交 ÷ 加购 | **做时间序列**：涨 = 承接改善；跌 = 比价 / 凑单 |
| **CPC** | 花费 ÷ 点击 | 判断"买贵了"还是"买偏了" |
| **点击率（CTR）** | 点击 ÷ 展现 | ⚠️ 判读需**展现 ≥ 200** |
| **渠道效率倍数** | 渠道转化率 ÷ 店铺（或该品）平均转化率 | 见 §4 |
| **ROI** | 成交金额 ÷ 花费 | ⚠️ **三口径**，见下 |

### 1.3 ⚠️ ROI 三口径（不可混用）

| 口径 | 分子 | 用途 |
|---|---|---|
| **平台口径** | 平台报表给的成交 | 只作参考，**不可直接用于决策** |
| **自算 ROAS** | 自己按归因规则重算的成交 ÷ 花费 | 交叉验证 |
| **净口径** | 扣除退款 / 剔除未回补后的成交 ÷ 花费 | **决策只看这个** |

> **同一份花费，三个口径可以差出 30%。** 引用时必须写明用的是哪个。

### 1.4 ⚠️ 「进步 / 退步」是分位名次的变化

后台常给「较日常」「同类商品排行」「分位」这类标注。
**「进步 / 退步」讲的是名次变化，不是指标值变化。**

> 实测：转化率 **14.84%（同类前 8%）** 被标注 `↓退步 1%` ——
> 意思是**名次掉了 1 位**，**转化率本身并没有下降**。
> 解读时**绝不能**说"转化率上升 / 下降"。

## 2. 自洽校验清单（每次出数后必跑）

```
【加总校验】
  分日加总        == 页面区间合计
  场景明细加总    == 场景合计
  计划明细加总    == 计划合计
  渠道明细加总    == 账户合计
  地域分省加总    == 地域合计

【派生比率校验】（容差 ±3%）
  ROI        ?= 成交金额 ÷ 花费
  转化率     ?= 支付买家数 ÷ 访客数
  CPC        ?= 花费 ÷ 点击
  点击率     ?= 点击 ÷ 展现
  客单价     ?= 支付金额 ÷ 支付买家数
  人均浏览量 ?= 浏览量 ÷ 访客数

【跨后台锚】（最强校验）
  后台 A 的某分项花费  ==  后台 B 的同期分日加总
  ← 两个独立后台能对上，说明两边都没取错

【结构校验】
  退款原因归类占比合计 == 100%
  推广三组件（全站+关键词+店铺直达）== 账户合计
```

**任何一条不过 → 先查数，不要写结论。**

推荐直接跑：`python scripts/verify_report.py <报告.html>`

## 4. 渠道效率判据

### 4.1 渠道的「主动 / 被动标签」

| 类型 | 渠道 | 含义 |
|---|---|---|
| **主动标签** | 搜索、购物车、我的淘宝、店铺 | 买家**带着需求**来的 → **转化天然高** |
| **被动标签** | 推荐（猜你喜欢、有好货等）| **平台推给他**的 → 转化天然低 |

**推论**：
- 推荐流量涨而转化低 → **常态，不是故障**（§SKILL 6.6）
- **搜索转化才是真本事**（唯一能自己控制的筹码）
- **渠道效率倍数** = 该渠道转化率 ÷ 该品平均转化率

### 4.2 倍数高的三种成因（药方完全不同）

| 成因 | 含义 | 药方 |
|---|---|---|
| **A. 渠道路径短** | 该渠道本就离成交近（如购物车）| 不用改 |
| **B. 流量精准** | 该渠道来的人需求明确 | 加大投入 |
| **C. 流量基数极小** | 样本不足，倍数不可信 | **先看量，再看效率** |

> ⚠️ **必须区分**：把 C 当成 B 去加投，就是拿噪声当信号。

## 5. ⛔ 脆弱定位禁区（最高优先级）

> **禁止依赖全页面文本顺序、`indexOf`、固定位置等脆弱定位方式。
> 必须先定位指标自己的结构化容器，再从该容器内部提取数值、趋势、排行、单位和时间范围。**

### 5.1 为什么这是"最高优先级"

数字为真，但**语义归属错了**。它 **不报错、不崩、看起来正常** ——
却会把"转化前 8%"读成"前 53%"，据此下一个**完全相反**的结论。

> **错误数据比没有数据危害大十倍。**

### 5.2 四步强制流程

1. **先 dump 原始 token 序列**（带 index + `repr`）—— **不是先写解析逻辑**
2. **找锚点 token 反推 offset** —— 不用 `indexOf`，不数"第 N 个数字"
3. **写断言**：关系不成立时返回 `None`（**宁缺勿错**）
4. **数学恒等式交叉校验**（§2）

### 5.3 实战教训

> 某后台页面的数据已抓到，但解析全 `None`。连续两轮改解析逻辑无效。
> **dump 一眼就看出 offset 猜错了** —— 真实结构是六元组：
> `标签 | 值 | 较日常 | 涨跌 | 同类商品排行 | 分位`，
> 标签在「较日常」**前二位**（我猜的是前一位，结果取到了值）。

**结论：「数据在、解析不出」的第一动作永远是 dump，不是改逻辑。**

### 5.4 典型的"看起来对但其实错"

| 陷阱 | 表现 | 破法 |
|---|---|---|
| **对比期值被当成当日值** | 读到"支付金额 +14.22%"，其实那是**对比期**的数字，当日实为 −12.25% | 用**恒等式**验：金额 ÷ 买家数 = 客单价 |
| **趋势图标顺序对齐** | 图标是**空元素**，靠顺序读必错 | 在**该指标自己的容器内**读图标 |
| **懒加载缺行** | 首次渲染只出 8~9 行 | 断言行数，不足返回 `None` |
| **残留值** | 切换周期后卡片数字不刷新 | 与"分日加总"对不上即弃用 |
| **URL 参数被默认值覆盖** | 传 `dateType=recent7` 渲染成 `day` | URL 带全参 → 点按钮 → **读数前断言** |
| **取回上一页 HTML** | 导航未生效，抓到缓存页 | 导航后**先断言 `location.href`** |

### 5.5 结构化取数的正确姿势（示例）

```javascript
// ❌ 脆弱：靠全文文本顺序
const idx = body.indexOf('支付金额');
const val = body.slice(idx, idx + 20);

// ✅ 结构化：先定位"指标自己的容器"，再在容器内取值
const cells = [...document.querySelectorAll('.oui-index-cell')];
const out = cells.map(c => ({
  label: c.querySelector('.oui-index-cell-title')?.innerText.trim(),
  value: c.querySelector('.oui-index-cell-value')?.innerText.trim(),
  trend: c.querySelector('.oui-index-cell-trend-up')  ? 'up'
       : c.querySelector('.oui-index-cell-trend-down') ? 'down' : null
}));
```

> `trend` 用**三目**给出三态：`up` / `down` / `null`（无趋势时**返回 null，不硬猜**）。

## 6. 语义陷阱汇总

1. **「进步/退步」= 名次变化**，不是指标值变化
2. **「支付买家数」≠「支付件数」**（人 vs 件）
3. **「客单价」（÷ 人）≠「件单价」（÷ 件）**
4. **跳失率 / 退款率上升 = 变差**（方向与其他指标相反，单元格必须加文字标注）
5. **地域报表不含全站推广**（页面自述）→ 主力在全站推广时，地域结论**只代表关键词场景**
6. **店级指标 ≠ 单品指标**（地域 / 访客分析多为**店铺级**）→ 作代理时**必须标注**
7. **页面上"优化建议"是广告，不是数据**（"点击率落后同水平商家""一键升级智能优化"）
   → **不得引用为证据**
8. **退款原因 ≠ 责任归属**：主观冲动 / 规格信息 / 品质物流 → **三类药方完全不同**
9. **平台给的 ROI ≠ 可决策的 ROI**（§1.3 三口径）
